一、视频完成检测逻辑优化
================================================================

【问题描述】
1. 视频播放结束后不会自动切换到下一个视频
2. 反而触发"视频进度无变化"的卡停恢复机制
3. 导致点击视频中央，使视频重新开始播放

【根本原因】
- 之前依赖ended属性和进度>98%判断
- 检测顺序错误：先检测卡停，再检测完成
- 导致完成后误触发恢复机制

【解决方案】
✅ 完全采用无题目版本的成功逻辑

1. **以实际播放进度为准**（最关键）
   - 获取视频总时长 video.duration
   - 计算目标时长 = duration * 95%
   - 当实际播放进度 >= 目标时长时，视为完成

2. **优化检测顺序**
   - 先检测是否完成（优先级最高）
   - 再检测是否卡停（避免完成后误触发）

3. **移除ended属性依赖**
   - 不再依赖ended属性（不可靠）
   - 只看currentTime实际播放进度

【代码位置】
文件: code/zhidao_web_auto_player_with_quiz.py
行号: L3176-L3196

【关键代码】
```python
# 获取视频总时长
video_duration = self.driver.execute_script("""
    var video = document.querySelector('video');
    if (video) {
        return video.duration;
    }
    return 0;
""")

if video_duration and video_duration > 0:
    # 以实际播放进度为准，达到95%就结束
    min_percentage = 0.95
    target_time = video_duration * min_percentage
    
    if current_progress >= target_time:
        self.logger.info(f"✅ 视频实际播放进度({current_progress:.0f}秒)已达到目标({target_time:.0f}秒/{video_duration:.0f}秒)，播放完成！")
        video_completed = True
        break
```

二、视频恢复点击优化
================================================================

【问题描述】
视频卡停恢复时点击两次，导致视频暂停
- 第一次点击：启动播放
- 第二次点击：暂停播放（❌）

【解决方案】
移除"策略2：再次点击确保播放恢复"的代码
- 只保留一次点击即可
- 避免第二次点击导致暂停

【代码位置】
文件: code/zhidao_web_auto_player_with_quiz.py
行号: L2116-L2139（已删除）
