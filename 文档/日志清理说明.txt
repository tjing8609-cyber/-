日志自动清理功能说明
========================================

【版本】v3.3.2

【功能】多重清理机制 - 运行次数 + 任务开始/结束时检查


========================================
一、功能说明
========================================

自动清理机制
----------------------------------------
✅ 机制1：运行次数计数清理
   - 运行次数记录：每次运行时自动记录在progress.json中
   - 清理触发条件：每运行20次触发一次日志清理
   - 触发时机：程序初始化时（__init__）

✅ 机制2：任务开始时检查
   - 检查时机：run()方法开始时
   - 检查条件：日志文件大小 > 20MB
   - 触发清理：超过阈值立即清理

✅ 机制3：任务结束时检查
   - 检查时机：run()方法finally块中
   - 检查条件：日志文件大小 > 20MB
   - 触发清理：超过阈值立即清理

清理策略：
   - 清理阈值：10000行
   - 保留行数：最后5000行
   - 清理对象：zhidao_account1.log、zhidao_account2.log、zhidao_account3.log


为什么需要多重清理
----------------------------------------
1. 运行次数清理（每20次）
   - 定期维护，防止日志无限增长
   - 适用于频繁运行的场景

2. 任务开始时检查（>20MB触发）
   - 确保任务开始前日志文件不会太大
   - 防止影响日志写入性能
   - 给用户清晰的清理提示

3. 任务结束时检查（>20MB触发）
   - 任务完成后最后检查
   - 确保下次运行前日志文件大小合理
   - 双重保障机制


清理阈值和条件
----------------------------------------
运行次数清理：
  - 触发检查：run_count % 20 == 0
  - 清理阈值：日志行数 > 10000行
  - 保留行数：最后5000行
  - 删除行数：前面的旧行数

文件大小清理：
  - 触发检查：任务开始/结束时
  - 清理阈值：文件大小 > 20MB
  - 保留行数：最后5000行
  - 删除行数：前面的旧行数


========================================
二、技术实现
========================================

运行次数计数
----------------------------------------
位置：progress_*.json文件

新增字段：
{
  "completed_videos": [...],
  "total_watched": 100,
  "last_update": "2025-10-29 10:30:00",
  "run_count": 15  ← 新增运行次数计数
}

每次运行时自动+1


check_and_cleanup_logs() 方法
----------------------------------------
调用时机：__init__() 初始化时

功能：
1. 读取progress.json中的run_count
2. run_count += 1
3. 检查是否 run_count % 20 == 0
4. 如果是，调用cleanup_old_logs()
5. 保存更新后的run_count


cleanup_logs_if_needed() 方法
----------------------------------------
调用时机：run()方法开始和结束时

功能：
1. 检查日志文件大小
2. 如果 > 20MB，调用cleanup_old_logs()
3. 否则显示文件大小信息

代码示例：
```python
def cleanup_logs_if_needed(self):
    """根据日志大小判断是否需要清理"""
    if not os.path.exists(self.log_file):
        return
    
    file_size = os.path.getsize(self.log_file)
    file_size_mb = file_size / (1024 * 1024)
    
    if file_size_mb > 20:
        self.logger.info(f"🚨 日志文件过大({file_size_mb:.2f} MB)，触发清理...")
        self.cleanup_old_logs()
    else:
        self.logger.info(f"📊 日志文件大小: {file_size_mb:.2f} MB，无需清理")
```


cleanup_old_logs() 方法
----------------------------------------
清理逻辑：

```python
def cleanup_old_logs(self):
    # 读取日志文件
    with open(self.log_file, 'r', encoding='utf-8') as f:
        lines = f.readlines()
    
    # 如果超过10000行
    if len(lines) > 10000:
        # 保留最后5000行
        keep_lines = lines[-5000:]
        
        # 添加清理标记
        cleanup_header = [
            "="*60,
            f"日志清理时间: {datetime.now()}",
            f"清理说明: 运行20次后自动清理，保留最近5000行",
            f"删除行数: {len(lines) - 5000} 行",
            f"保留行数: 5000 行",
            "="*60
        ]
        
        # 写入清理后的内容
        with open(self.log_file, 'w', encoding='utf-8') as f:
            f.writelines(cleanup_header)
            f.writelines(keep_lines)
```

六、常见问题
========================================

Q1：如何查看当前运行了多少次？
----------------------------------------
A：打开对应的 progress_account*.json 文件，查看 run_count 字段

例如：
{
  "completed_videos": [...],
  "total_watched": 100,
  "last_update": "2025-10-29 10:30:00",
  "run_count": 15  ← 当前运行15次
}


Q2：可以手动触发清理吗？
----------------------------------------
A：可以，有两种方式：

方式1：修改progress.json
- 将run_count改为19
- 下次运行时会触发清理

方式2：手动删除日志文件
- 直接删除zhidao_account*.log
- 下次运行会自动创建新文件


Q3：如果不想每20次清理一次怎么办？
----------------------------------------
A：修改源代码中的清理间隔：

文件：zhidao_web_auto_player_final.py
位置：check_and_cleanup_logs() 方法

修改：
if current_run_count % 20 == 0:  # 改成其他数字
    self.cleanup_old_logs()

例如：
- 每10次清理：% 10 == 0
- 每30次清理：% 30 == 0
- 每50次清理：% 50 == 0


Q4：清理会丢失重要日志吗？
----------------------------------------
A：不会。清理逻辑：
- 只在日志超过10000行时才清理
- 保留最近5000行（最新的日志）
- 删除的是旧日志（前面的行）
- 最近的运行记录都会保留


Q5：清理失败会影响程序运行吗？
----------------------------------------
A：不会。清理过程：
1. 使用try-except捕获异常
2. 清理失败只记录错误
3. 程序继续正常运行
4. 不影响视频/PPT处理


Q6：为什么选择5000行？
----------------------------------------
A：经过权衡：
- 5000行 ≈ 4-5 MB
- 包含最近几天的运行记录
- 足够用于问题追溯
- 文件大小合理，不影响打开速度

七、使用建议
========================================

建议1：定期检查运行次数
----------------------------------------
每周检查一次progress.json中的run_count：
- 确认计数正常
- 了解使用频率
- 预估下次清理时间


建议2：清理后验证日志
----------------------------------------
清理后检查日志文件：
- 确认清理标记正确
- 确认保留的日志完整
- 确认文件大小合理


建议3：保留清理记录
----------------------------------------
清理信息会显示在控制台：
============================================================

建议截图或记录，以备后用。


建议4：大文件及时清理
----------------------------------------
如果日志文件已经很大（>50MB）：
1. 手动删除旧日志
2. 或者将run_count改为19
3. 下次运行触发清理


建议5：备份重要日志
----------------------------------------
如果某次运行很重要：
1. 运行前备份当前日志
2. 运行后分析日志
3. 确认无误后可删除备份
